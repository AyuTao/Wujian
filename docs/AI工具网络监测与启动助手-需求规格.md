# 无间道：需求规格

版本：1.1 · 更新：2026-10-21 · 状态：目标需求基线；当前实现与验证见《开发进度》，系统级保护尚未实现。

正式项目名为“无间道”，仓库名为 wujian。本版加入用户确认的系统级强制要求；项目按非商业开源用途设计。

## 1. 产品目标与已确定的选择

让用户在使用指定 AI 工具前检查网络环境，在授权保护后以系统规则约束其联网路径。系统级保护是正式版必备能力：出口不符合明确的允许地区策略、DNS 泄露或必要证据无法确认时，禁止开放业务路径，并处理覆盖范围内的已有连接。

- 桌面平台：macOS、Windows、Linux；共用 Tauri 界面，系统检测和保护分别适配。
- 无需注册本软件账号、检测服务账号或填写第三方 API Key。
- 采用本地配置检查和直接 API 请求，不抓取第三方检测网页，不依赖浏览器扩展。
- 非商业版本采用 ipify 查询公网 IP，采用 ip-api DNS 接口提供范围明确的解析观测。
- 用户授权保护后，先建立限制，再执行检测；满足必要条件时只开放允许路径，限制持续保留。
- 界面简洁、有操作反馈；以工具列表、状态和下一步操作为核心，详细证据按需展开。

不提供节点、代理订阅或跨境中转服务。首版提供修改建议，自动变更仅限经用户授权、由本软件管理的保护规则。DNS、路由、浏览器和整机 IPv6 设置的通用一键修复不进入首版。

## 2. 用户与首版工具范围

主要用户已有自己的合法获授权网络环境，希望检查配置、观察变化，并控制指定 AI 工具的网络访问。

| 工具 | 首批计划 | 保护上线条件 |
| --- | --- | --- |
| Claude Code | 发现安装位置、添加到列表、检测、在系统终端启动 | 针对实际安装形态验证执行程序、进程边界及相关连接 |
| Codex CLI | 同上 | 同上；不能根据同名进程推定已保护 |
| Claude 桌面应用 | 安装发现和手动添加；完整保护为后续适配 | 完成应用包、辅助进程及存量连接验证 |
| 用户提到的 agy 及其他工具 | 手动添加条目；具体产品、安装形态和能力后续确认 | 未适配前只展示可完成的检查，不宣称支持保护 |

原生二进制、脚本包装器、npm 安装和共享运行时分别识别。不能为保护一个 CLI 而直接封禁整台机器的 Terminal、node 或 Python。

“发现工具”“能够启动”“能够保护”是三项独立能力。WSL、容器、虚机及 SSH 远端属于独立环境，宿主结果不能自动覆盖。

## 3. 两种使用方式

### 3.1 仅检测

本地发现工具 → 读取配置 → 用户选择是否开启外部检测 → 展示结果和修改建议。

该方式不安装访问控制规则，也不提供无保护启动入口。界面明确显示“系统保护未实现/未启用”；从其他入口启动的工具不受本软件限制。

### 3.2 启用保护

选择支持的工具 → 确认允许路径、保护范围和必要检查 → 系统授权 → 建立并验证限制 → 独立检测 → 必要条件符合后允许指定路径 → 持续监测。

必要条件失败、未知或过期时，不进入“按策略放行”。诊断请求不借用 AI 工具身份，不为了取得基线而临时开放 AI 工具的全部访问。

如果软件版本、系统或安装形态尚不支持保护，继续提供检测，并说明缺少的能力。此状态不能用一个模拟开关替代。

## 4. 首次打开与后续启动

首次打开不运行 AI 程序、不触发登录、不读取账户密钥。通过固定安装位置、PATH、应用清单及用户指定位置发现工具；不扫描整块磁盘。

引导集中完成三件事：选择工具；确认已有联网路径和外部检测告知；选择仅检测或授权保护。外部告知列明服务、可见信息和传输方式，允许用户单独关闭外部 DNS 观测。

首次读到的配置只能记录为现状，不能自动标为正确基线。用户确认的策略需要保留版本。

已运行的工具需单独处理：说明之前流量不在此次保护范围；只有存量连接处理能力验证完成后才可显示保护成功，否则要求用户结束相关会话后重启。不能用“未观察到连接”证明没有存量连接。

后续启动重新核对工具身份、策略版本、网络变化和规则实际状态。工具升级或路径变化时，不直接沿用失效的身份绑定。

## 5. 状态与放行条件

保护状态与检测状态独立存储、独立显示。

| 保护状态 | 用户含义 |
| --- | --- |
| 未启用 | 当前只有检查与提醒 |
| 正在建立 | 已申请设置，尚未确认限制生效 |
| 限制中 | 当前范围的限制已确认生效，尚未开放业务路径 |
| 按策略放行 | 允许路径已开放，禁止路径的限制仍有效 |
| 保护故障 | 无法确认规则或辅助服务状态，不能保证正在限制 |
| 不支持 | 当前平台或工具形态尚无已验证的保护能力 |

检测状态包括：未检测、检测中、符合、偏离、待核查、无法确认、已过期、不适用。每项带检测时间、执行路径、适用范围和证据来源。

强制必要条件：系统保护覆盖声明的全部入口；系统授权有效；规则和已有流控制已确认；允许路径有效且出口符合明确的允许地区策略；DNS 解析被约束在允许路径；受保护范围的 TCP/UDP、IPv4/IPv6 策略满足要求；与工具实际路径绑定的必要证据未过期。未配置允许地区或无法确认时不放行。CN 禁止，其他地区按用户明确选择的标签判断。

辅助建议项：普通 DNS 外部观测、单次 IP 变化及变化频率。普通 HTTPS IP 查询、无完整性保护的 HTTP DNS 观测不能冒充工具实际路径的强制证据；不得单独授权放行。不提供“忽略必要项但继续显示保护成功”的入口。

采用用户手册的预设：受保护范围禁止 IPv6 公网通信。检查与实施以所选工具范围为准，不默认改动整机开关。IPv6 请求失败、没有 AAAA 或只有链路本地地址，均不单独构成完整验证。

不设置“防封分”“安全 IP 分”或地区一致性评分。出口允许地区为必要条件；住宅标签、ASN、系统语言、时区不作为默认强制条件。地理数据存在误差，不能承诺服务可用或账户安全；尚未选定并实现地区数据 Provider。

## 6. 检测内容与结果边界

### 6.1 本地检查

- 活动接口、路由、系统代理、所选工具可读取的代理设置及环境变量；敏感值脱敏。
- 系统 DNS、本机存根、按域名解析策略、本地 DNS 监听及可读取的现有代理配置。
- macOS 检查 `/etc/resolver` 与系统解析状态；Windows 检查有效网卡 DNS、NRPT 等；Linux 识别实际解析管理器与配置目标。
- 普通用户权限不足、命令不存在和读取失败均显示未知，不视为通过。
- 对现有 Clash-AI-Guard 检查域名来源、受管理解析文件、本地服务和同步任务；不运行用户原有安装脚本，不接管原有规则。

### 6.2 公网 IP 与变化

ipify 只返回本次请求所见公网地址。分别标识助手默认路径与显式选定的代理路径；不静默回退直连，不将探测站出口自动命名为“Claude 实际出口”。

记录路径、地址族、来源与时间；同路径、同地址族的结果才比较变化。目标服务器地址、Fake-IP、代理入口地址不充当公网出口。远端按目的地分配出口时，即使选了相同本地代理，也不能保证 AI 服务看到相同 IP。

工具运行期间默认每 60 秒查询一次 IP；网络变化立即使旧结果失效。频繁变化提醒默认参考值为滚动 30 分钟内 3 次，支持调整；该数值仅是提醒阈值。

### 6.3 DNS 观测

ip-api 使用随机测试域名观察该次查询对应的解析出口及可能返回的客户端子网。必须区分系统解析、代理远端解析和工具相关证据，不能把代理端解析结果标成系统 DNS。

测试域名与 AI 域名可能采用不同分流策略；此结果不证明所有 AI 请求的 DNS 路径一致。DNS 与 HTTP 出口不同、国家不同或出现多个解析服务器，均不能单独判为泄露。`edns` 字段缺失不证明没有泄露。

官方免费端点文档示例为 HTTP、缓存 60 秒，并限制非商业使用。本项目按非商业用途集成，清楚标注传输方式；HTTPS 支持在开发验证阶段核实，不预设可用，也不在 HTTPS 失败后暗中改为 HTTP。HTTP 观测需在首次外部检测告知中明确选择，不参与可信放行判断。

默认在工具运行时每 10 分钟或网络变化后检测 DNS；退避与服务限制优先。请求失败标为“无法确认”，不计为 IP 变化或 DNS 泄露。

## 7. 保护功能的范围与生命周期

保护只允许用户确认的网络路径，持续阻止覆盖范围内的禁止路径。必须明确保护的是“此应用的所有受支持入口”，还是“从助手创建的受控会话”；后者不能显示为前者。

只具备 DNS 按域名约束时，不能宣称已实现应用级完整阻断。应用自有 DoH、直接 IP、缓存、UDP、IPv6、子进程、共享系统解析服务和已有连接需要分别核实。当前无法满足用户所选范围时，不启用该范围的保护承诺。

原生网络规则负责访问限制；轮询负责观测和触发收紧。仅靠 API 观测无法保证在远端出口变化前拦截请求，也无法撤回已经发出的流量。没有工具实际路径与稳定出口的可验证关联时，不得开放严格保护模式。具体实现边界见[系统级强制保护方案](系统级强制保护方案.md)。

| 事件 | 期望行为 |
| --- | --- |
| 本地代理退出 | 禁止路径的规则仍有效；允许路径不可用，提示并复测 |
| 网络切换、休眠恢复 | 旧检测过期；按已验证的平台策略收紧允许范围后复测，并记录处理延迟 |
| UI 窗口关闭或崩溃 | 系统辅助服务与规则继续按已确认策略工作；重新打开后查询真实状态 |
| 辅助服务故障或权限撤销 | 验证剩余规则状态，显示保护故障；不能假定仍阻断或已经解除 |
| 用户暂停外部检测 | 停止探测；规则仍保留。必要证据过期则转限制中 |
| 用户解除保护 | 明确说明影响；只撤销本软件拥有的规则并核验结果 |
| 更新或卸载 | 保留或移交规则期间不制造无保护窗口；卸载提供可验证的清理和恢复路径 |

出现明确偏离时可依据已授权策略自动收紧访问。恢复默认需要复测成功后由用户点击“恢复访问”，避免反复放行；以后可增加显式选择的自动恢复。

首次启用保护时，可在此前确认的范围内于必要检查通过后自动开放允许路径。因异常而收紧后的再次开放属于“恢复访问”，必须单独点击；“启动工具”不能隐含代替恢复。

## 8. 修改建议与隐私

建议固定说明：观察到什么、影响什么、在哪里调整、涉及哪些工具、如何复测。只对有证据的策略冲突要求处理，其余显示待核查。

本软件默认不上传工具列表、完整路径、进程参数、AI 域名历史、代码、聊天和日志。外部服务会看到本次请求来源 IP、随机测试域名及必要网络元数据；不把测试请求发送到开发者的转发服务器。

配置和最近记录默认保存在本机，记录保留 7 天且可调整、关闭或删除。导出默认隐藏公网 IP、用户名和路径，可预览后选择是否包含。现有本地代理控制接口的凭据按需读取或保存到系统凭据存储，不成为注册前置条件。

项目非商业运营与源码许可证分别声明。发布说明标注第三方检测服务的适用条款；不使用“保证防封”“绝不泄露”或地区访问资格承诺。

## 9. 版本交付与验收

下表是目标开发顺序；当前已经实现的检测预览和验收结果见《开发进度》，本表不代替实际支持矩阵。

| 阶段 | 交付 | 完成标准 |
| --- | --- | --- |
| 0.1 界面样机 | 工具首页、首次引导、详情、记录、设置及模拟状态 | 全程标注界面演示；动效、键盘和空态可检验 |
| 0.2 检测预览 | 三平台本地检查、API、变化记录和建议；原生保护完成前不开放受保护启动 | 真实状态来自后端；无注册依赖；各平台能力和未知项准确 |
| 0.3 保护试验 | 优先在开发者现有 macOS 验证一个工具，再逐平台扩展 | 先限后测、持续限制、故障恢复及解除保护全部有证据 |
| 1.0 正式版 | 三平台已列明工具的检测与经过验证的保护 | 每个平台与工具组合有覆盖矩阵；未覆盖能力保持不可用 |

发布阻断能力前，必须验收以下场景：首次建立限制后才探测；其他入口启动的实际覆盖；存量连接；子进程与共享运行时；TCP/UDP 与 IPv4/IPv6；系统 DNS 与应用自有解析；代理退出；网络切换和休眠；UI/辅助服务故障；权限变化；工具升级；只撤销本软件规则的回滚。

外部服务超时、限流、格式变化、TLS 错误与 HTTP 数据被篡改，均不能误放行。浏览器、宿主、WSL、容器和远端结果不能互相冒充。所有验收保存平台版本、工具形态、策略版本、步骤、期望、实际及证据。
