# 无间道：整机系统隔断

更新：2026-10-21。一个工程、一套 Rust 策略与命令协议，macOS、Windows、Linux 分别调用本机防火墙接口。本文描述当前源码与验收边界，不能当作三平台均已完成实测。

## 共同策略

用同一份 Country.mmdb 提取 CN IPv4 网段，加上明确的本地地址范围。限制模式拒绝非 CN、未知公网 IPv4 和公网 IPv6，规则不局限于 TCP 或新启动工具。保留局域网、回环、链路本地及 CGNAT/Tailscale 内网地址。国家记录缺失时不猜测归属；GeoIP 可能过期或出错。

按 IP 分类不等于按网站或 AI 服务分类：CN、本地地址上的中继仍可能访问海外；Fake-IP、TUN 内层目标与代理外层地址须结合实测。系统配置回读与实际流量验收是不同证据，回执的 enforcementVerified 保持 false，启动门禁不会拿这些回执当成 AI 环境安全证明。

## 共用入口

- 准备规则：只读数据库，导出可审查规则和影响说明，不执行管理员操作。
- 启用：用户确认影响后通过本机管理员授权运行同一 Rust helper 入口。界面本身不以管理员身份运行。
- 核验：读取当前系统规则、地址条件和本软件保存的代次；不依赖前端布尔值。
- 解除：仅删除本软件拥有的规则资源，提供无需联网的本地恢复入口。

操作通过系统目录中的文件锁串行；状态文件只允许管理员修改。用户设置、DNS、时区、代理配置和下载隔离属性不随隔断操作自动修改。规则不会因窗口退出自动撤销；重启后的持续保护和后台异常监测仍未实现。

## 平台适配

| 平台 | 执行方式 | 清理边界 |
| --- | --- | --- |
| macOS | PF 专属叶 anchor，复用当前 com.apple/* wildcard；先检查可达性与优先级，规则和表逐项回读 | 只清理 com.apple/000.io.wujian，释放本软件 -E 引用；不重载 /etc/pf.conf、不整体关闭 PF |
| Windows | NetSecurity 防火墙组，计算允许地址的精确补集后分批建立双向阻断；检查启用配置、本地策略合并、方向和实际地址条件 | 只删除 Wujian.Firewall 中带本软件 owner 的规则；不重置 Windows 防火墙 |
| Linux | nftables 独立 inet 表，input/output/forward base chain；一次事务替换，本机每包过滤，不使用 established 快捷放行 | 只删除 inet wujian_guard，不 flush ruleset；检测到 flowtable 时保守拒绝启用 |

Mac 的 PF 既有 state 可绕过后续规则，所以启用前必须提示并确认一次全部 PF 连接状态重置。这会影响国内连接、代理和远程连接。缺少可达 wildcard、存在更早可绕过的入口或网卡 skip 时拒绝启用；不会偷偷改写主防火墙。

Mac App 使用 ad-hoc 签名，不依赖个人 Apple 开发者证书。先前 NE 工程保留为实验备份，不是产品必装组件。移除下载隔离的 xattr 不授予网络过滤权限；PF 仍需要管理员授权。Linux 桌面授权依赖 polkit/pkexec 与已安装的 nftables；Windows 使用 UAC。

## 当前验证与下一步

已完成共用 CIDR 补集、规则生成、三平台适配源码、Tauri 命令接入与操作入口；本机实际数据库生成 6,317 个 CN IPv4 网段和 12,929 个阻断 CIDR。Mac 的实际 PF 文件已通过 -n 只解析检查。

源码级测试覆盖未知地址、公网 IPv6、地址边界、命令注入、PF anchor 可达性、Windows 地址条件和规则方向、nftables 所有权及执行器超时。CI 增加 Mac 语法检查、Windows WhatIf 参数检查、Linux 隔离 network namespace 内的现有 TCP/UDP/IPv6 阻断与恢复测试；远程 CI 尚未运行。

当前未完成三平台真实断流验收、后台守护、出口变化/DNS/WebRTC 异常自动切断、核验后确认恢复。HTTP DNS 观测不能授权自动开放访问，单次 IP 查询不证明 AI 服务看到相同出口。旧按工具严格判定引擎继续作为启动门禁，整机执行器不伪造该引擎需要的安全证据。

首次管理员联调发现命令退出/管道等待问题，已改为 std 子进程回收和完整等待超时；正在重新核验授权链路，不能把打包成功当作隔断成功。
