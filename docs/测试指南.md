# Wujian 0.1.0-beta.1 测试指南

这是一份测试版验收清单。请在自己的可本地操作、可恢复的测试电脑或虚拟机上执行断流测试。整机隔离会中断 SSH、远程桌面和局域网连接；不要把唯一恢复入口放在网络另一端。

## 1. 获取与启动

从本仓库 Releases 获取对应系统和 CPU 的测试包及同名 `.sha256`，对照 SHA-256。未发布的草稿只供仓库维护者查看；普通测试者须等维护者发布测试版。

- macOS 14+：本版 ad-hoc 签名，未经 Apple 公证。仅在确认来源后按系统提供的“仍要打开”流程启动；不必关闭 Gatekeeper。
- Windows：安装包未签名，首次操作原生规则需 UAC，依赖 Windows Defender Firewall；受组织策略管理的设备可能拒绝本地规则。
- Linux：桌面会话需 polkit/pkexec，规则需要 nftables，读取路由需要 iproute2。DNS 修改仅支持运行中的 systemd-resolved/resolvectl；NetworkManager 等可能随后覆盖运行时 DNS，须复测。

先记录系统版本、CPU、代理客户端版本、当前模式、TUN 与 DNS 设置，并保留自己原来的静态 DNS 配置。首次启动默认不授权外部查询、不修改系统网络。

## 2. 只读检查（先做这一组）

1. 启动后确认显示真实平台，未申请管理员权限，DNS/IPv6 未变化。
2. 点击右上角 ⚙，进入“检测授权与路径”。HTTPS 查询向 api.ipify.org 发送请求；HTTP DNS 采样使用随机子域名 `*.edns.ip-api.com`，明文且可被篡改，两项分别选择。
3. 若使用系统/应用代理，填入客户端实际监听的本机代理 URL，例如 `http://127.0.0.1:7890`，保存后重新检查。不要填写账号密码；所选代理失败时应报错，不允许静默改为直连。
4. 核对 DNS 原值、出口 IP/地区、IPv6、两个采样路由与客户端模式。模式可能未知；规则模式不能变成“Global”。缺少 Country.mmdb 时国家未知，不能默认美国。
5. 连续点击重新检查，应不因按钮本身清空仍有效的出口证据。切换网络后旧证据应过期。
6. 点击 DNS 和 WebRTC 浏览器复测。页面会运行 JavaScript、使用当前浏览器的 DNS/WebRTC 配置；curl 只抓页面不能代替这些测试。HTTP DNS 的单次结果不能把 DNS 项标成全路径已核验。

## 3. DNS 写入与恢复

1. 在设置弹层的“DNS 设置”填入确实存在的解析器 IPv4。程序先向 UDP 53 查询 example.com；填写未运行的 127.0.0.1 时应拒绝修改，原值不变。
2. 使用可用解析器，确认后申请管理员权限。取消时应显示错误，不显示修改成功。
3. 授权后用系统工具核对实际配置。静态原值与 DHCP/自动模式分别测试。
4. 点击“恢复本工具配置”，原始静态 DNS 应完整回来；原先自动的接口才恢复自动。Linux 还原修改前的运行时每接口列表，不承诺覆盖网络管理器的持久配置。
5. 多接口部分失败时保留恢复记录。重试只处理未完成的接口；恢复失败不能显示成功。

## 4. IPv6 与 Kill Switch（测试机）

1. 保存工作。“阻断公网 IPv6”请求管理员权限并提示连接可能重置。核验规则后 IPv4 应继续可用，公网 IPv6 应被规则阻断；原网卡手动 IPv6 参数不应被删除。
2. 完成外部授权、代理配置和只读检查，再启用监测。出口、国家、采样 TUN 路由或 IPv6 证据不足时，会请求管理员权限进行整机隔离。取消授权必须显示“隔离未确认”。
3. 在关键证据健康时重测，不应仅因重测动作隔离。切换网络、关闭 TUN、断开代理或使出口证据过期，观察触发、授权、回读是否一致。轮询及授权存在延迟；请记录实测耗时，不能据此宣称毫秒断流。
4. 授权隔离后，同时测试新建/已建立的 TCP、UDP、公网 IPv4/IPv6、局域网和外部 DNS。严格模式应只允许回环地址。规则回读成功仍须做实际数据包验收。
5. 隔离期间重新检测不应自动解除规则。重启应用保留隔离事件，显示需核验；系统重启后规则是否仍在须重新核验，不能凭保存的回执认定隔离。
6. 点击“停止防护并解除隔离”，确认后恢复本工具规则与 DNS；验证普通联网及原有其他防火墙规则仍正常。全部恢复前应用拒绝普通退出，不代表操作系统不能强制结束进程。

本版本不能保证“崩溃即自动阻断”；应用尚未请求/获得授权时，没有后台特权服务替它加载隔离规则。请将这个边界作为测试结论记录。

## 5. 本机紧急恢复

优先重新打开应用，使用“恢复本工具配置”。不应清空整套系统防火墙，也不要删除恢复记录来掩盖失败。

若 UI 无法使用，可以从源码构建 `wujian-firewall`，在本机管理员终端执行两个固定类型请求。先将以下内容分别保存为 `release.json` 和 `dns-release.json`：

```json
{"action":"release","policy":null,"dns":null,"acknowledge_connection_reset":false}
```

```json
{"action":"network-release","policy":null,"dns":null,"acknowledge_connection_reset":false}
```

```sh
cargo build --manifest-path src-tauri/Cargo.toml --locked --bin wujian-firewall
# macOS/Linux，在本机终端分别执行；Windows 在管理员 PowerShell 去掉 sudo。
sudo src-tauri/target/debug/wujian-firewall request /完整路径/release.json
sudo src-tauri/target/debug/wujian-firewall request /完整路径/dns-release.json
```

已安装的主程序也支持 `--firewall-helper /完整路径/release.json`，同样需要管理员终端；macOS 可执行文件位于 app 的 `Contents/MacOS/wujian`。执行后重新打开 UI，恢复本工具配置以同步用户态记录。原始恢复文件损坏时会明确报错，不能用“恢复 DHCP”冒充恢复静态原值。

## 6. 提交反馈

在右上角设置弹层的“诊断日志”查看或导出 JSON。导出包含版本、平台、时间、会话 ID、操作和错误类别，不含原始 IP、命令、代理凭据、用户路径或恢复备份；日志约 2 MiB 轮转。详细系统错误显示在当前 UI，提交截图前仍需自行检查隐私。

请在 GitHub Issues 写明：版本/系统/CPU、复现步骤、预期与实际、是否取消管理员授权、规则回读结果、实际断流结果、能否恢复，并附脱敏日志。不要上传 Country.mmdb、恢复备份、代理订阅、节点配置或原始设置文件。
