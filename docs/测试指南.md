# Wujian 0.1.0-beta.2 测试指南

这是一份测试版验收清单。请在自己的可本地操作、可恢复的测试电脑或虚拟机上执行断流测试。整机隔离会中断 SSH、远程桌面和局域网连接；不要把唯一恢复入口放在网络另一端。

## 1. 获取与启动

从本仓库 Releases 获取对应系统和 CPU 的测试包及同名 `.sha256`，对照 SHA-256。未发布的草稿只供仓库维护者查看；普通测试者须等维护者发布测试版。

- macOS 14+：本版 ad-hoc 签名，未经 Apple 公证。仅在确认来源后按系统提供的“仍要打开”流程启动；不必关闭 Gatekeeper。
- Windows：安装包未签名，首次操作原生规则需 UAC，依赖 Windows Defender Firewall；受组织策略管理的设备可能拒绝本地规则。
- Linux：桌面会话需 polkit/pkexec，规则需要 nftables，读取路由需要 iproute2。DNS 修改仅支持运行中的 systemd-resolved/resolvectl；NetworkManager 等可能随后覆盖运行时 DNS，须复测。

先记录系统版本、CPU、代理客户端版本、当前模式、TUN 与 DNS 设置，并保留自己原来的静态 DNS 配置。首次启动默认不授权外部查询、不修改系统网络。

## 2. 只读检查（先做这一组）

1. 启动后确认显示真实平台，未申请管理员权限，DNS/IPv6 未变化。
2. 点击右上角 ⚙，进入“检测授权与路径”。HTTPS 查询向 api.ipify.org 发送请求；HTTP DNS 采样使用随机子域名 `*.edns.ip-api.com`，明文且可被篡改，两项分别选择。
3. 若使用系统/应用代理，填入客户端实际监听的本机代理 URL，例如 `http://127.0.0.1:7890`，保存后重新检查。不要填写账号密码；所选代理失败时应报错，不允许静默改为直连。
4. 核对 DNS 原值、出口 IP/地区、IPv6、两个采样路由与客户端模式。模式可能未知；规则模式不能变成“Global”。模式与采样网卡仅供参考，不阻止使用其他 VPN 或显式代理。缺少 Country.mmdb 时国家未知，不能默认美国。
5. 连续点击重新检查，应不因按钮本身清空仍有效的出口证据。切换网络后旧证据应过期。
6. 在浏览器中进行 DNS 和 WebRTC 复测。页面会运行 JavaScript、使用当前浏览器的 DNS/WebRTC 配置；curl 只抓页面不能代替这些测试。HTTP DNS 的单次结果不能把 DNS 项标成全路径已核验。

## 全局 TUN 保护的 DNS 兼容回归

- 准备 Global + TUN 环境，分别使用未写代理组的 DNS、`respect-rules`、显式 `#DIRECT`、加密 DNS 域名等配置。DNS 字段诊断应提示具体原因，不应单凭上游写法阻止准备计划；不得把配置未确认显示成已经发生泄漏。
- 核对确认框中的 DNS 提示。规则加载与回读仍须成功；切回规则模式、停用 TUN、改变节点或破坏防火墙规则，不能继续声称保护有效。
- 保护加载后实际测试域名解析、浏览器 DNS/WebRTC，以及新建和已建立连接。未确认的 DNS 地址不得成为物理网卡例外。若客户端本身尝试公网直连 DNS，可能无法解析；这与 App 自动改写客户端配置不同。
- 导出日志应保留 `guard.dns.*` 的 `warning` 分类，且不包含原始解析器 URL、策略域名、代理组名、节点或凭据。

## 3. DNS 配置监测与原值恢复

1. 记录代理客户端中的 DNS 分流策略与系统 DNS。主界面 DNS 行显示实际采样的解析器 IP 与地区，无独立“复查”按钮；“DNS 配置”行分别显示网卡保存值与系统生效入口，设置页显示逐网卡配置与最近读取时间。模拟 TUN 的 114 入口与物理网卡 1.1.1.1 并存，应分开显示；不得继续把生效入口当成网卡静态值或显示为无泄露 PASS。右上角重新核验及守护中的采样统一更新出口与 DNS 行，不应修改系统或 Clash 配置。
2. 国内 DNS 可以存在，HTTP DNS 辅助采样仅供参考，不应因为地区为中国或辅助服务超时而触发隔离。
3. 开启守护时锁定可读取的系统 DNS 配置。修改解析器地址、macOS `/etc/resolver` 作用域、systemd-resolved 每链路 DNS/域，应触发隔离；修改网站的 CDN 解析答案不属于配置变化。
4. 不承诺检测到未暴露的 Clash/VPN 内部上游变化或浏览器自有 DoH。若需要改变这些设置，停止守护，在客户端修改后复测并重新开启。
5. 旧版本或显式 IPC 修改过系统 DNS 时，“恢复本工具配置”仍通过原生恢复记录还原原先的静态值／自动模式。没有备份时，不得把网卡 DNS 重置为默认。
6. 停止守护后，在 DNS 设置中输入 1 至 4 个 IPv4 地址并显式应用。验证先测试可用性，授权后备份并写入，取消授权或失败不能显示成功。分别用微信与 Safari 访问同一个视频号链接，记录加载结果；成功后停止保护不应回退旧 DNS；失败时用恢复操作核对原 DNS 值。不得仅因 DNS 或域名解析成功就报告视频播放正常。
7. macOS / Windows 分别连接 Wi-Fi、有线网卡，再让一块断网或停用，使用手动输入、Cloudflare、Google 及主界面“改海外”。核对每块现有物理网卡的静态 IPv4 DNS；停止保护和重启 App 后不应由本工具还原。新插入/已拔除网卡不应伪称已修改；Linux 目前仅活动接口运行时 DNS，不承诺重启或网络管理器重配后保留。
8. 先停止保护、完全退出 Clash，再写入系统 DNS，然后重启和退出 Clash；如仍变化，比较客户端恢复操作及网卡静态值。macOS 用 `networksetup -getdnsservers "Wi-Fi"` 等逐服务检查，`scutil --dns` 仅表示当前解析入口。日志核对 `dns.commit` 后的 `dns.physical` 与 `dns.effective` 分类；若只有后者变为 `domestic`，不能报告物理网卡被改回。读取失败应显示未知，不沿用上次值伪称实时。模拟 DNS 写入/回读失败、回执中断，以及重试时增加/拔除网卡，恢复记录不得丢失。
9. 分流片段需填写客户端已有的真实代理组。核对 CN 与 DIRECT 使用国内 DNS，国外 DoH 明确指定代理组；生成和复制不应修改客户端文件。合并后须在客户端重载，并核对流量规则，不能只验证 DNS 所在国家。

## 4. IPv6 与 Kill Switch（测试机）

1. 保存工作。“阻断公网 IPv6”请求管理员权限并提示连接可能重置。核验规则后 IPv4 应继续可用，公网 IPv6 应被规则阻断；原网卡手动 IPv6 参数不应被删除。
2. 完成外部授权、代理配置和只读检查，再启用监测。出口／地区、DNS 配置、指定时区或 IPv6 证据不足时，会请求管理员权限进行整机隔离。取消授权必须显示“隔离未确认”。
3. 在关键证据健康时重测，不应仅因重测动作隔离。切换网络、关闭 TUN、断开代理或使出口证据过期，观察触发、授权、回读是否一致。轮询及授权存在延迟；请记录实测耗时，不能据此宣称毫秒断流。
4. 授权隔离后，同时测试新建/已建立的 TCP、UDP、公网 IPv4/IPv6、局域网和外部 DNS。严格模式应只允许回环地址。规则回读成功仍须做实际数据包验收。
5. 隔离期间重新检测不应自动解除规则。重启应用保留隔离事件，显示需核验；系统重启后规则是否仍在须重新核验，不能凭保存的回执认定隔离。
6. 点击“停止防护并解除隔离”，确认后解除本工具规则、恢复未完成或旧版的 DNS 事务；成功提交的 DNS 应保持新值；验证普通联网及原有其他防火墙规则仍正常。全部恢复前应用拒绝普通退出，不代表操作系统不能强制结束进程。

本版本不能保证“崩溃即自动阻断”；应用尚未请求/获得授权时，没有后台特权服务替它加载隔离规则。请将这个边界作为测试结论记录。

## 5. 本机紧急恢复

优先重新打开应用，使用“恢复本工具配置”。不应清空整套系统防火墙，也不要删除恢复记录来掩盖失败。

若 UI 无法使用，可以从源码构建 `wujian-firewall`，在本机管理员终端执行两个固定类型请求。先将以下内容分别保存为 `release.json` 和 `dns-release.json`：

```json
{
  "action": "release",
  "policy": null,
  "dns": null,
  "acknowledge_connection_reset": false
}
```

```json
{
  "action": "network-release",
  "policy": null,
  "dns": null,
  "acknowledge_connection_reset": false
}
```

```sh
cargo build --manifest-path src-tauri/Cargo.toml --locked --bin wujian-firewall
# macOS/Linux，在本机终端分别执行；Windows 在管理员 PowerShell 去掉 sudo。
sudo src-tauri/target/debug/wujian-firewall request /完整路径/release.json
sudo src-tauri/target/debug/wujian-firewall request /完整路径/dns-release.json
```

已安装的主程序也支持 `--firewall-helper /完整路径/release.json`，同样需要管理员终端；macOS 可执行文件位于 app 的 `Contents/MacOS/wujian`。执行后重新打开 UI，恢复本工具配置以同步用户态记录。原始恢复文件损坏时会明确报错，不能用“恢复 DHCP”冒充恢复静态原值。

## 6. 提交反馈

在右上角设置弹层的“诊断日志”查看或导出 JSON。导出合并 App 与管理员 helper 日志，包含版本、平台、构建提交（可用时）、时间、会话/操作 ID、操作、耗时和错误类别，不含原始错误、IP、命令、代理凭据、用户路径或恢复备份。App 和系统保护日志各约 2 MiB 轮转；查看仅显示 App 最近 100 条。Windows/Linux 导出系统保护日志可能请求授权，取消后仍会保存 App 日志，并明确标记系统部分未收集。导出中的 appHealth 与 system.health 表示是否有写入丢弃、文件读取失败或损坏行。详细系统错误显示在当前 UI，提交截图前仍需自行检查隐私。

请在 GitHub Issues 写明：版本/系统/CPU、复现步骤、预期与实际、是否取消管理员授权、规则回读结果、实际断流结果、能否恢复，并附脱敏日志。不要上传 Country.mmdb、恢复备份、代理订阅、节点配置或原始设置文件。

## 严格守护回归用例

仅在可本地恢复的测试机或虚拟机执行真实断流测试；不要在远程维护链路上测试。

- 四项检查均就绪时开启：锁定当次出口、DNS 配置与时区，确认公网 IPv6 阻断规则回读。目标时区可在设置明确指定；留空锁定当前值，不默认洛杉矶。
- 分别只改变一项：出口 IP、系统 DNS 配置、目标时区；停用本工具规则且让物理网卡仍允许公网 IPv6。每次均应触发整机隔离。规则被其他管理员修改需重新授权核验，本版本尚无独立特权守护来持续验证内核规则。
- 关闭代理、使 HTTPS 出口查询失败、制造证据过期或网络切换：应请求隔离。长时间外部请求期间，本机巡检仍继续。
- 未满足四项条件时开启：不得把失败证据当作安全基线，应进入隔离。未开启守护时，检查失败只显示待检查，不能显示“已断路”。
- 明确拒绝／取消管理员授权：显示“隔离未确认”，保留触发原因，可在设置重试；不得显示已经实际断网。
- 用其他 VPN、显式 HTTP／SOCKS 代理、国内外分流配置重复测试：未知 Mihomo 模式或没有 TUN 本身不触发隔离。
- 隔离后恢复诊断数据：不能自动联网。明确停止并恢复后重新核验，只有再次开启才建立新基线。
- 时区对齐／恢复、IPv6 阻断／恢复均只处理本工具修改。恢复不能把原静态 DNS、手工 IPv6 配置或未曾修改的时区覆盖为默认值。
- 打开应用后，第一次需要改时区、开启保护、修改 DNS 或阻断 IPv6 时只弹一次管理员授权，安装同一个常驻组件。之后这些操作不得再弹授权。取消后再次打开不得询问；明确点击这些操作才再次询问。组件已安装但没有响应时不得重复弹授权。查询先走 ipinfo.io，失败时再查 ipwho.is；前后出口一致才修改。美国不同城市应按返回的 IANA 时区处理；缺少时区、返回 IP 不符、查询失败或网络变化不应修改。普通刷新不能触发城市查询；守护中禁用跟随。管理员取消时须显示失败，原值恢复记录保留。

## 系统国家/地区跟随回归

1. 分别以 CN、HK、MO 作为当前用户地区，确认界面语言保持原样。出口国家确认后核对系统设置保存值；国家确认但城市时区缺失时，地区独立更新，时区保留。
2. 出口地区未知时不写系统设置，不默认美国；主界面应显示“建议修改”，设置页能打开系统国家/地区设置。
3. Windows 检查国家/地区与区域格式，界面语言及非 Unicode 程序语言保持原样。macOS 检查地区，并核对界面语言列表未改变。
4. Linux 分别验证 GNOME、KDE 和 systemd 用户格式环境。目标 locale 未安装、LC_ALL 覆盖或工具不可用时应明确提示，不能报告成功；重启应用或重新登录后检查日期、数字、货币格式及界面语言。
5. 修改过程中失败时保留原值记录；恢复仅覆盖本工具持有的字段。外部修改地区后，不自动覆盖；恢复不能抹掉新的手动设置。恢复完成后自动跟随暂停，点击立即跟随可重新启用。
6. 导出日志检查 `region.read`、`region.follow`、`region.decision`、`region.apply`、`region.restore`；不得包含原始 IP、用户路径、完整偏好或账户资料。
